# Architecture decisions

> Журнал ключевых технических решений для `relocate_helper`.  
> Промпт 1 — начальная фиксация; дополняется на следующих этапах.

**Дата:** 2026-07-27

---

## ADR-001: Task queue — RQ (Redis Queue)

| Поле | Значение |
|------|----------|
| **Статус** | Принято |
| **Контекст** | ТЗ §8.1 требует одну очередь задач на MVP: Dramatiq **или** RQ. Redis уже входит в стек (кэш, rate limit, брокер). |
| **Решение** | **RQ** (`rq` + `redis`) |
| **Альтернативы** | Dramatiq (больше возможностей, чуть сложнее конфигурация); Celery (тяжелее для старта, явно не рекомендован для MVP) |
| **Обоснование** | RQ проще для текущего объёма: минимальный API, один Redis-брокер, понятный worker-процесс, достаточен для ingestion/processing pipeline MVP. Dramatiq не добавляет критичных возможностей на этапе 1. |
| **Последствия** | Worker запускается отдельным контейнером/процессом (`relocate-helper-worker`). Scheduler и cron-подобные задачи — через отдельный процесс или admin-trigger до появления потребности в APScheduler/Celery Beat. Retry/backoff — реализуются в обёртках задач (промпт 14). |
| **Пересмотр** | При росте нагрузки (>10k задач/час), необходимости приоритетных очередей или встроенного scheduler — оценить миграцию на Dramatiq или Celery. |

## ADR-002: Modular monolith layout

| Поле | Значение |
|------|----------|
| **Статус** | Принято |
| **Контекст** | ТЗ §8.2 описывает логические модули в одном репозитории. |
| **Решение** | Пакет `src/relocate_helper/` с подмодулями: `bot`, `admin`, `ingestion`, `processing`, `retrieval`, `answering`, `billing`, `db`, `workers`, `common`, `api`. |
| **Обоснование** | Единый деплой для MVP, чёткие границы доменов, возможность выделения сервисов позже без переписывания. |
| **Последствия** | FastAPI — точка входа API/health; aiogram-бот и admin UI подключаются как отдельные entrypoints позже. |

## ADR-003: Configuration — pydantic-settings

| Поле | Значение |
|------|----------|
| **Статус** | Принято |
| **Решение** | `pydantic-settings` с fail-fast валидацией обязательных production-параметров в `Settings.validate_production_requirements`. |
| **Обоснование** | Типизация, валидация на старте, единый источник конфигурации для API, worker и тестов. |

## ADR-004: Local infrastructure — Docker Compose

| Поле | Значение |
|------|----------|
| **Статус** | Принято |
| **Решение** | PostgreSQL 16 + pgvector, Redis 7, MinIO (S3-compatible), app, worker. |
| **Обоснование** | Соответствует ТЗ §8.1; воспроизводимая локальная среда без облачных секретов. |
