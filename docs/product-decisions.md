## Легенда статусов

| Статус | Значение |
|--------|----------|
| `pending` | Требует решения владельца; реализация не должна зашивать значение в код |
| `proposed` | Безопасный конфигурируемый default; можно использовать в dev/staging до подтверждения |
| `confirmed` | Утверждено владельцем |
| `deferred` | Сознательно отложено; не блокирует текущую фазу |

### 1.4 Источники данных

| Поле | Значение |
|------|----------|
| **Статус** | `confirmed` |
| **Выбранное значение** | Источники **добавляются владельцем вручную** по мере поступления через **поле ввода в admin UI** (ссылка/username Telegram, загрузка файла, транскрипт и т.д.). Фиксированный список на старте **не задаётся**. |

| **Ответственный** | владелец проекта |
| **Дата пересмотра** | до paid production |
| **Влияние на реализацию** | Admin CRUD источников с формой добавления; `sources.legal_basis` nullable; валидация sync без обязательного legal_basis в test mode |

### 2.3 Пороги достаточности ответа

| Сценарий | Min evidence | Min confidence | Поведение |
|----------|--------------|----------------|-----------|

| Fallback по chunks | ≥2 chunks | 0.55 | «единичные упоминания» |
